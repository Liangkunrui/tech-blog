## 1. 项目概述

### 1.1 项目背景

作为 Java 后端的第一个完整项目，通过实现一个「技术博客 + 社区互动」系统，打通 **SpringBoot + MyBatis-Plus + Redis + RabbitMQ + MySQL** 的完整使用链路，把理论知识落到真实业务场景中。

### 1.2 项目目标

- 完成一个可运行、可演示的博客社区系统（B 端 Web 接口 + 简单前端页面）
- 覆盖主流后端技术点：JWT 认证、缓存、消息队列、异步任务、数据库设计与优化
- 产出清晰可复用的工程骨架与代码规范，作为后续项目的基础

### 1.3 名词定义

| 名词 | 说明 |
| ---- | ---- |
| 游客 | 未登录用户，可浏览文章与评论 |
| 用户 | 注册登录后的用户，可发布文章、互动、接收通知 |
| 管理员 | 维护分类/标签、审核评论（可选） |

## 3. 用户角色与核心流程

### 3.1 角色

| 角色 | 权限 |
| ---- | ---- |
| 游客 | 浏览文章列表/详情、查看评论、查看分类标签 |
| 注册用户 | 游客权限 + 发布/编辑/删除自己的文章、评论、点赞、收藏、关注、查看通知 |
| 管理员（可选） | 维护分类/标签、删除违规内容、评论审核 |

### 3.2 核心业务流程

1. **注册登录**：用户注册 → 密码 BCrypt 加密存储 → 登录签发 JWT → 后续请求携带 Token 鉴权
2. **发文流程**：用户编写 Markdown → 保存文章 → 异步刷新相关缓存 → 通知粉丝
3. **阅读流程**：浏览列表（分页/筛选）→ 查看详情（Redis 缓存 + 浏览量统计）→ 点赞/收藏/评论
4. **互动通知**：被评论/点赞/收藏/关注 → 生成站内信通知 →（可选）异步邮件通知

## 5. 非功能需求

### 5.1 性能与缓存

- **文章详情/列表**：Redis 缓存，设置合理过期时间；写操作后主动失效或更新（Cache Aside 模式）
- **点赞**：Redis Set 记录点赞用户，点赞数缓存，定时批量回写 MySQL
- **浏览量**：Redis 计数（INCR），定期落库
- **热点文章**：缓存热点 TopN，避免冷热不均（防缓存击穿/穿透，使用空值缓存或互斥锁）

### 5.2 异步化（RabbitMQ）

- 发布文章 → 异步刷新列表/详情缓存
- 新文章 → 异步通知粉丝（站内信/邮件）
- 评论触发 → 异步写通知
- 评论审核（可选）→ 延时队列，超时自动放行或通知管理员

### 5.3 安全

- 密码 BCrypt 加密存储，禁止明文
- JWT 无状态认证，Token 过期时间与刷新策略
- 接口权限控制：作者本人才能改删自己的文章
- 参数校验（Bean Validation），防止 SQL 注入（MyBatis 参数化）

### 5.4 数据与可用性

- 核心表加索引（详见 6.2），慢查询优化
- 统一异常处理与统一响应结构
- 逻辑删除保留数据，便于恢复与统计

## 6. 数据库设计（初稿）

> 仅列核心表，字段以开发阶段细化 DDL 为准；所有表包含 `id`、`create_time`、`update_time`，需要软删除的表包含 `deleted`。

### 6.1 表清单

| 表名 | 说明 | 关键字段 |
| ---- | ---- | ---- |
| `user` | 用户表 | username(唯一)、password、nickname、avatar、email、bio、status |
| `article` | 文章表 | user_id、category_id、title、content(Markdown)、summary、status(草稿/已发布/已删除)、view_count、like_count、favorite_count、comment_count |
| `category` | 分类表 | name、sort |
| `tag` | 标签表 | name(唯一) |
| `article_tag` | 文章-标签关联表 | article_id、tag_id（联合唯一索引） |
| `comment` | 评论表 | article_id、user_id、parent_id(二级回复)、content、status(待审核/通过) |
| `article_like` | 点赞表 | article_id、user_id（联合唯一索引） |
| `favorite` | 收藏表 | article_id、user_id（联合唯一索引） |
| `follow` | 关注表 | user_id(被关注者)、follower_id(粉丝)（联合唯一索引） |
| `notification` | 通知表 | user_id(接收者)、from_user_id、type(评论/点赞/收藏/关注/系统)、target_id、content、is_read |

### 6.2 索引优化要点

- `article`：`status` + `create_time`（列表查询）、`category_id`、`user_id`
- `comment`：`article_id` + `status`
- 关联表：`(article_id, user_id)` 联合唯一索引
- `notification`：`user_id` + `is_read`（未读计数）

## 7. 接口设计概览（RESTful，前缀 `/api`）

| 模块 | 方法 | 路径 | 说明 |
| ---- | ---- | ---- | ---- |
| 认证 | POST | `/api/auth/register` | 注册 |
| 认证 | POST | `/api/auth/login` | 登录，返回 JWT |
| 用户 | GET | `/api/users/me` | 当前用户信息 |
| 用户 | PUT | `/api/users/me` | 修改个人信息 |
| 用户 | GET | `/api/users/{id}` | 用户主页信息 |
| 用户 | GET | `/api/users/{id}/articles` | 某用户的文章 |
| 文章 | GET | `/api/articles` | 分页列表（分类/标签/关键词/排序） |
| 文章 | GET | `/api/articles/{id}` | 详情（浏览量+1） |
| 文章 | POST | `/api/articles` | 发布 |
| 文章 | PUT | `/api/articles/{id}` | 编辑 |
| 文章 | DELETE | `/api/articles/{id}` | 逻辑删除 |
| 分类/标签 | GET | `/api/categories`、`/api/tags` | 列表 |
| 评论 | GET/POST | `/api/articles/{id}/comments` | 列表 / 发表 |
| 点赞 | POST/DELETE | `/api/articles/{id}/like` | 点赞 / 取消 |
| 收藏 | POST/DELETE | `/api/articles/{id}/favorite` | 收藏 / 取消 |
| 关注 | POST/DELETE | `/api/users/{id}/follow` | 关注 / 取关 |
| 通知 | GET | `/api/notifications` | 通知列表（分页） |
| 通知 | GET | `/api/notifications/unread-count` | 未读计数 |
| 通知 | PUT | `/api/notifications/{id}/read` | 标记已读 |

## 9. 验收标准（总）

1. 注册、登录、JWT 鉴权闭环可用，未登录访问受保护接口返回 401
2. 文章发布→列表→详情→编辑→删除全流程可用，Markdown 正常渲染
3. 评论、点赞、收藏、关注数据正确，点赞去重、计数准确
4. 通知在互动发生后异步生成，未读计数正确
5. Redis 缓存生效（详情/列表/点赞/浏览量），写操作后缓存一致
6. RabbitMQ 异步刷新缓存与发送通知可正常消费，无重复通知
7. 核心接口有分页与索引，接口响应符合统一结构
