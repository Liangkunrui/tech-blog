# 技术博客 / 社区系统 开发计划

- 版本：v0.1（初稿）
- 状态：规划中
- 前置条件：需求文档 v0.1 评审通过

---

## 1. 总体安排

采用「阶段式迭代、每阶段可验收」的方式，预计 **2~3 周**（按业余时间每天 2~3 小时估算，共约 60~80 小时）。

| 阶段 | 内容 | 交付物 | 预计工时 |
| ---- | ---- | ---- | ---- |
| 阶段 0 | 环境与工程搭建 | 可启动的工程骨架、统一响应/异常、MyBatis-Plus 配置 | 1 天 |
| 阶段 1 | 用户模块 | 注册登录（JWT + SpringSecurity）、个人中心 | 2~3 天 |
| 阶段 2 | 文章模块 | 文章 CRUD、Markdown 渲染、分类标签、列表/详情 | 3~4 天 |
| 阶段 3 | 互动模块 | 评论、点赞、收藏、关注 | 2~3 天 |
| 阶段 4 | 消息通知 | 站内信、邮件（异步），RabbitMQ 接入 | 1~2 天 |
| 阶段 5 | 缓存与队列深化 | 热点缓存、缓存一致性、延时队列（审核） | 1~2 天 |
| 阶段 6 | 测试与部署 | 单元测试、接口联调、Docker 部署、README 完善 | 1~2 天 |

**里程碑**

| 里程碑 | 内容 | 时间点 |
| ---- | ---- | ---- |
| M1 | 工程骨架 + 用户注册登录闭环 | 第 1 周末 |
| M2 | 文章发布与浏览闭环（含分类标签、缓存） | 第 2 周末 |
| M3 | 互动 + 通知 + 缓存/队列优化，全流程可演示 | 第 3 周末 |

---

## 2. 各阶段详细任务

### 阶段 0：环境与工程搭建（1 天）

**任务**
- [ ] 本地安装/确认环境：JDK 17、Maven、MySQL 8、Redis、RabbitMQ（Docker 或本机）
- [ ] 通过 Spring Initializr 创建 SpringBoot 工程（web、security、validation、mysql、redis、amqp）
- [ ] 引入 MyBatis-Plus（含分页插件、逻辑删除配置）与 JWT 依赖
- [ ] 统一响应结构 `Result<T>`、统一异常处理 `@RestControllerAdvice`
- [ ] `application.yml` 多环境配置（dev / prod），`application-local.yml` 不进 git
- [ ] 初始化数据库脚本目录 `sql/`，编写建库语句与核心表 DDL
- [ ] 使用 MyBatis-Plus 代码生成器生成 entity / mapper / service（可选，先手写 1~2 张表体会）
- [ ] 健康检查接口 `/api/health` 可访问

**验收**：工程可启动，能连 MySQL/Redis/RabbitMQ，统一响应与异常生效

### 阶段 1：用户模块（2~3 天）

**任务**
- [ ] `user` 表 DDL 与实体、Mapper
- [ ] 注册接口（用户名唯一校验、密码 BCrypt 加密）
- [ ] 登录接口（校验密码、签发 JWT、返回用户信息）
- [ ] SpringSecurity 配置：放行 `/api/auth/**` 与文章浏览接口，其余需 Token
- [ ] JWT 过滤器：解析 Token、注入当前用户；Token 过期处理
- [ ] 获取当前用户、修改个人信息、修改密码
- [ ] 个人中心：我的文章 / 收藏 / 关注 / 粉丝（列表接口）
- [ ] 接口测试（Postman / curl 完整跑通）

**验收**：注册→登录→携带 Token 访问受保护接口闭环可用；未带 Token 返回 401；密码加密存储

### 阶段 2：文章模块（3~4 天）

**任务**
- [ ] `article`、`category`、`tag`、`article_tag` 表与实体
- [ ] 文章发布（含分类/标签处理）、编辑、逻辑删除（仅作者）
- [ ] 文章分页列表：按分类/标签/关键词筛选，按最新/热度排序
- [ ] 文章详情：Markdown 内容返回 + 前端渲染（或后端转 HTML）
- [ ] 浏览量统计：Redis `INCR` + 定期/异步落库
- [ ] 文章详情/列表 Redis 缓存（Cache Aside），发布/编辑/删除后主动失效
- [ ] 分类管理、标签管理接口，分类文章数统计
- [ ] 草稿功能（可选，P2）

**验收**：发文→列表→详情→编辑→删除全流程可用；缓存命中生效；浏览量准确

### 阶段 3：互动模块（2~3 天）

**任务**
- [ ] `comment`、`article_like`、`favorite`、`follow` 表与实体
- [ ] 评论：发表、列表（分页）、（可选）二级回复
- [ ] 点赞：Redis Set 去重、点赞数缓存、定时回写 MySQL
- [ ] 收藏/取消收藏、收藏列表
- [ ] 关注/取关、粉丝与关注列表
- [ ] 互动后触发通知事件（先打日志，阶段 4 接入 MQ）
- [ ] 更新文章计数（评论数、点赞数、收藏数）与缓存

**验收**：各互动数据正确、点赞去重计数准确、互斥操作（重复点赞/收藏）幂等

### 阶段 4：消息通知（1~2 天）

**任务**
- [ ] `notification` 表与实体
- [ ] 接入 RabbitMQ：互动/发文后发送消息，消费者异步生成站内信
- [ ] 通知列表（分页）、未读计数、标记已读
- [ ] 邮件通知（可选）：异步发送（spring-boot-starter-mail）
- [ ] 消费失败重试与去重（防止重复通知）

**验收**：被评论/点赞/收藏/关注后能收到通知；未读计数正确；MQ 宕机恢复后消息不丢（手动 ack）

### 阶段 5：缓存与队列深化（1~2 天）

**任务**
- [ ] 热点文章缓存：TopN 列表缓存、空值缓存/互斥锁防穿透与击穿
- [ ] 缓存一致性梳理：写路径（更新 DB → 失效缓存）与并发场景验证
- [ ] 评论审核延时队列（可选）：RabbitMQ TTL + 死信队列，超时自动放行
- [ ] 点赞/浏览量批量落库任务（定时任务）
- [ ] 慢 SQL 排查与索引补充

**验收**：高并发浏览下缓存命中率明显提升；缓存与 DB 数据一致；延时队列按预期触发

### 阶段 6：测试与部署（1~2 天）

**任务**
- [ ] 核心接口单元测试 / 集成测试（认证、文章、互动）
- [ ] 全流程联调：注册→发文→浏览→互动→收通知
- [ ] Docker Compose 编排：MySQL + Redis + RabbitMQ + 应用
- [ ] 编写部署文档与 README 完善
- [ ] （可选）部署到云服务器 / 内网环境演示

**验收**：可一键启动整套环境，按 README 步骤从零跑通全部功能

## 3. 风险与对策

| 风险 | 影响 | 对策 |
| ---- | ---- | ---- |
| 缓存与 DB 不一致 | 用户看到脏数据 | 统一 Cache Aside 策略，写后失效；必要时双删/延迟双删 |
| 热点文章缓存失效导致击穿 | 瞬时 DB 压力大 | 互斥锁重建缓存、热点 Key 永不过期 + 主动更新 |
| 缓存穿透（恶意查不存在 ID） | DB 被无效查询打爆 | 空值缓存 + 布隆过滤器（可选） |
| JWT 登出/续期不完善 | 安全体验问题 | 短 Token + Redis 黑名单或 refresh token 机制 |
| RabbitMQ 环境与运维成本 | 阶段 4 卡住 | 先用 Docker 起单机，重点掌握生产者/消费者/确认机制 |
| 范围膨胀（草稿、审核等 P2） | 周期拉长 | P2 需求全部后置，M3 验收后按需追加 |
| 点赞/浏览量频繁写库 | 性能差 | Redis 计数 + 定时批量落库 |

## 4. 学习要点对照（本项目的意义）

| 技术 | 在项目中学到什么 |
| ---- | ---- |
| SpringBoot + SpringSecurity | 认证授权流程、过滤器链、注解鉴权 |
| MyBatis-Plus | 条件构造器、分页、逻辑删除、代码生成器如何提效 |
| Redis | 缓存设计（穿透/击穿/雪崩）、Set 去重、计数器、数据一致性 |
| RabbitMQ | 生产者/消费者、交换机与路由、异步解耦、延时队列（TTL+DLX） |
| MySQL | 表设计、索引优化、慢查询分析 |
| 工程化 | 分层架构、统一响应/异常、多环境配置、Docker 部署 |
